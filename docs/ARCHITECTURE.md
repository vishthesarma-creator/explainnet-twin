## Boundaries

- `contracts.py`: immutable, versioned Pydantic records. Optional measurement fields remain `null` when absent. `GroundTruth` is a separate record and SQLite table; no feature or diagnosis contract contains its label.
- `config.py`: version 1 YAML, absolute data/runtime/socket paths, loopback API host, objective and laboratory action policy. The configuration hash connects future run and snapshot results.
- `storage.py`: explicit `explainnet --config ... init` migration path. SQLite foreign keys, WAL transactions, record repositories and a persistent job queue. Migration 2 adds durable job payloads and network ownership metadata while preserving Stage 2 records.
- `jobs.py`: one worker thread with registered service, network lifecycle, path, probe and traffic handlers. Compare-and-update transitions prevent the same job being executed twice. Restart marks formerly running jobs `interrupted`; those jobs are not replayed.
- `agent.py` and `agent_server.py`: typed client and root-run stdlib server over a Unix socket in a root-owned directory. Peer UID allowlist plus socket mode restrict callers. The protocol allows health, capabilities, inventory and explicit Stage 3/4 laboratory operations. Arbitrary commands and future repair operations are unsupported.
- `api.py` and `cli.py`: loopback FastAPI service and explicit lifecycle commands. The API returns job IDs immediately and structured errors with request IDs. Future job types return HTTP 501.

## Units and time

RTT and jitter are milliseconds. Throughput, goodput and capacities are bits/second. Loss and utilization are fractions; display percentages multiply by 100. Counter-derived utilization above one is retained as invalid evidence, never clipped. Duration fields are seconds, with measured elapsed job time from `time.monotonic()` converted to milliseconds. Stored timestamps are timezone-aware UTC. Missing measurements are `null`, never zero-filled.

## Launch in the current WSL project

From PowerShell in the project folder, initialize storage once (safe to repeat):

```powershell
wsl.exe -d Ubuntu -- .venv/bin/explainnet --config config/example.yaml init
```

In a separate terminal, start the privileged laboratory agent. The UID is obtained from the ordinary WSL account; the service itself does not run as root.

```powershell
$appUid = (wsl.exe -d Ubuntu -- id -u).Trim()
wsl.exe -d Ubuntu -u root -- env PYTHONPATH=src python3 -m explainnet.agent_server --allow-uid $appUid
```

In another terminal, start and check the API:

```powershell
wsl.exe -d Ubuntu -- .venv/bin/explainnet --config config/example.yaml serve
wsl.exe -d Ubuntu -- .venv/bin/explainnet --config config/example.yaml status
```

Submit a job with `POST http://127.0.0.1:8765/v1/jobs/environment-check`, then read `GET /v1/jobs/{job_id}`. Stop the API cleanly with `wsl.exe -d Ubuntu -- .venv/bin/explainnet --config config/example.yaml stop`; stop the agent with Ctrl+C in its terminal. If the agent is absent, health is `degraded`; if storage is uninitialized, health is `unavailable` and job submission returns HTTP 503. No production networking resources are created by these commands.

## Stage 3 network owner and traffic

`topology/spec.py` validates and plans paths without importing Mininet. `network_contracts.py` exposes Pydantic operation types to the application. The agent validates the same restricted structure with stdlib code before resource creation. `network_runtime.py` imports OS Mininet only inside the privileged owner.

The agent holds each Mininet object, host namespace process and traffic subprocess for its entire lifetime. Its root-owned state directory (default `/var/lib/explainnet-agent`, configurable with `--state-dir`) is protected by a file lock. Atomic per-instance journals record names, interface indexes, host/process start ticks, namespaces, addresses, DPIDs, ports, configuration hashes and forwarding revisions. States are `starting`, `running`, `stopping`, `stopped` and `failed`.

Only live objects with matching OVS ownership tags are reported as running. API restart reconciles SQLite with the agent. Agent restart marks previous instances failed rather than treating a journal as a working Mininet object. Explicit cleanup checks bridge ownership, interface indexes and process start ticks before removing that instance. Repeated start with the same running configuration and repeated stop are idempotent. Cleanup never uses `mn -c` or blanket OVS/process removal.

For the cycle, each host pair has deterministic IPv4 and ARP forwarding in both directions, matched on ingress port and source/destination address. There is no `NORMAL`, learning or unrestricted flood rule. Rules use priority 200, OpenFlow 1.3 and an instance/pair cookie. Selecting one configured pair's path replaces only that cookie; other pairs retain their rules. The switch defaults to drop for unmatched traffic. Static neighbor entries and explicit ARP rules permit deterministic delivery even when a probe removes its source neighbor entry.
